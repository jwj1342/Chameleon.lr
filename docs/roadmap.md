# 研发路线

路线图表达当前优先级，不是日期承诺。阶段是否完成以可复现证据和退出条件为准；新模型、
UI 或分发渠道只有在解决当前最高风险后才进入实现。

## Now：巩固 MVP

目标是让现有链路成为可靠的研究与协作底座。

- 在真实 Lightroom Classic 中完成并记录 macOS / Windows Host Gate。
- 收集获得明确授权的参考、目标和最终人工调色配对数据。
- 固定离线评测格式：亮度距离、色差、裁切率、参数平滑度和人工接受率。
- 为失败样例建立可匿名化的最小 fixture 和回归测试。
- 校准当前曝光、Temperature 和 Tint 启发式的范围与置信度。

退出条件：MVP 自动检查持续通过；至少一个真实摄影数据集有来源、许可和基准报告；已知
失败模式能够被分类而不是只靠截图描述。

## Next：质量与批次一致性

- 引入相机配置文件、文件类型、ISO 和拍摄序列等上下文特征。
- 评估局部直方图、主体/背景区域和中性色区域，减少全局统计误判。
- 为低置信度结果提供跳过、警告和应用前摘要。
- 增加同一拍摄批次的参数平滑与异常点约束。
- 建立固定 Preset、当前基线和候选模型的可重复对照实验。

退出条件：候选方案在锁定评测集上稳定优于固定 Preset 和当前基线，并在摄影师盲评中
减少人工修正；失败时可以安全跳过，不产生极端滑杆。

## Later：可学习模型与产品化

- 在评测体系稳定后，探索监督学习、检索或可解释的混合模型。
- 评估本地常驻服务和 Socket 传输，前提是启动成本已成为可测量瓶颈。
- 完善批量预览、结果比较和用户反馈采集，但不牺牲 Lightroom 原生可编辑性。
- 为 macOS/Windows 引擎增加代码签名，完成 Apple notarization。
- 明确支持的 Lightroom/OS 矩阵、升级策略和回滚路径。
- 根据真实分发需求再评估 Adobe Marketplace；本地安装不依赖 Marketplace 注册。

## 暂不计划

- 上传用户照片到托管云服务。
- 绕过 Lightroom Catalog 写入不可编辑的最终渲染图。
- 在没有数据来源和评测协议前训练或发布大型模型。
- 将裁剪、修复、蒙版或生成式编辑混入“风格迁移”结果。

## 如何提出路线建议

请使用 Feature Request 模板，说明用户问题、可衡量的结果、对隐私/协议/宿主兼容性的
影响，以及为什么当前能力无法解决。路线图变更应优先围绕问题和验收标准，而不是先指定
某个模型或框架。
