# 项目定义

## 一句话说明

Chameleon.lr 是一个运行在 Lightroom Classic 与用户本机之间的智能调色工具：它从一张
已经完成调色的参考照片中提取风格，并针对不同曝光、白平衡和环境色的目标照片，逐张
推导可编辑、可撤销的 Lightroom Develop Settings。

## 用户问题

固定 Preset 本质上复用同一组参数。当拍摄跨越室内外、时间段、光源或曝光条件时，同一
Preset 往往产生偏色、肤色漂移、阴影堵塞或高光溢出。摄影师只能逐张修正，这会削弱批量
工作流的效率，也难以保持整组照片的视觉一致性。

本项目关注的是“保持风格意图，同时适应每张照片的成像条件”，而不是简单复制参数，也
不是把目标图渲染成一张不可继续编辑的新图片。

## 目标用户

- 需要批量交付婚礼、活动、人像或商业照片的 Lightroom Classic 用户。
- 希望保留 RAW 工作流、Catalog 历史和后续人工微调空间的摄影师。
- 研究可解释色彩迁移、Lightroom 自动化与摄影工作流的开发者。

## 产品目标

1. 从参考照片的渲染特征和 Develop Settings 中表达可迁移的风格意图。
2. 对每张目标照片独立估计曝光和白平衡差异，而不是盲目复制固定 Preset。
3. 只写入明确允许的物理滑杆，并通过一次 Catalog 事务保留 Undo 和历史记录。
4. 所有图像分析默认在本机完成；协议、诊断和临时文件的隐私边界清晰可审计。
5. 用可重复的 Demo、自动测试和摄影师评测数据衡量进步，而不是只凭主观截图。

## 当前非目标

- 不替代 Lightroom / Adobe Camera Raw 的 RAW 解码和颜色管理管线。
- 不进行云端图片上传、用户账户、团队素材库或 Marketplace 分发。
- 不迁移裁剪、Transform、蒙版、修复、降噪、锐化和镜头校正。
- 不承诺从单张参考图恢复其完整调色过程；渲染结果无法唯一反推出编辑历史。
- 不把当前全局统计基线描述为已训练、已校准或适用于商业生产的 AI 模型。

## 设计原则

### 非破坏性优先

结果必须是 Lightroom 可见、可继续调整的 Develop Settings。任何新增滑杆都需要经过
Lua 与 Python 双重白名单、范围验证和测试。

### 本地优先与最少数据

默认只传输完成计算所需的 JPEG 预览、允许的参数和有限元数据。临时文件在运行后删除；
诊断保留必须由用户主动开启。

### 协议先于实现

Lua 与 Python 通过版本化 JSON Schema 解耦。算法可以替换，Lightroom 侧的验证和 Catalog
事务边界不能被绕过。

### 先建立评测，再增加模型复杂度

每次算法演进都需要可重复输入、质量指标、失败样例和人工评审。模型更复杂并不自动代表
摄影结果更好。

## 成功标准

MVP 的工程验收记录在 [MVP 说明](mvp.md)。进入公开稳定版本前，还需要满足：

- 在获得授权且覆盖多场景的真实照片集上建立离线基准和回归阈值。
- 曝光、色偏、裁切率和批次参数平滑度有可量化改善。
- 摄影师盲评中，相比固定 Preset 显著减少逐张修正工作。
- 支持矩阵内的 Lightroom、macOS 和 Windows 组合通过实机回归。
- macOS/Windows 产物完成签名，macOS 产物完成 notarization。
- 数据保留、安全报告、故障诊断和回滚流程有清晰文档。

## 术语

| 术语 | 本项目中的含义 |
| --- | --- |
| 参考照片（Reference） | 当前活动且已完成风格调色的照片 |
| 目标照片（Target） | 同一次选择中需要适配风格的其他照片 |
| 风格（Style） | 可迁移的色调、HSL、曲线和 Color Grading 意图 |
| 自适应（Adaptation） | 根据目标照片特征估计的逐图曝光与白平衡修正 |
| Develop Settings | Lightroom Catalog 中可编辑、非破坏性的物理滑杆参数 |
| Engine | 读取请求、分析预览并返回建议参数的本地 Python 程序 |
| Host Gate | 必须在真实 Lightroom Classic 中完成的人工验收 |
